# Agent Note: GitHub 镜像页交互精修

Status: implemented

## Problem

镜像页精修反馈覆盖设置行紧凑度、关闭开关后的依赖操作、单一测试按钮、排序控件、弹窗材质、拼接方式选择和页面标题。此前页头右侧排序循环图标、测试失败时额外的“重试失败项”按钮，以及把镜像弹窗绑到全局材质的实现，与当前期望不符。

## Decision

- 设置行当前值与尾随尖头之间固定保留 8dp。镜像页标题使用与设置子页相同的 18sp Semibold。
- 显示顺序只按测得的最低延迟自动升序，全部失败时继续采用用户已有列表顺序；该显示排名不更改持久化镜像优先级。全量测试完成后选择有有效毫秒结果中的最小项；单项测试及停止批次不触发自动选择。
- 删除“重试失败项”独立按钮与上下移动排序按钮，只保留底部测试全部／停止主操作。稳定ID管理使用官方Miuix OverlayIconDropdownMenu锚定⋯；其中仅包含测试、编辑、删除。拼接方式在编辑器内保持单选设置行，但改用官方OverlayDropdownPopup以控制行首链路图标和标题样式。
- 新增／编辑采用底部显式保存；输入、失焦、键盘完成、关闭和系统返回均不写入。正式保存仍使用SettingsSession真实确认结果；失败与不确定操作保留草稿。删除镜像仅保留真正的二次确认弹窗。

- 删除排序模型及`mirror.order`显示偏好；首次普通设置写入时清除旧 key，镜像列表自身顺序继续作为请求失败回退顺序。旧偏好仍按通用未知 key 安全保留，直到本地设置下一次写入。
- 五个主目的地统一走Miuix `springAnimateToPage`；减少动态时直接换页。设置内部NavDisplay仍使用官方MiuixDefault转场。Miuix 0.9.4根主题已提供MiuixOverscrollFactory，所以标准滚动容器继续用单一主题回弹而非再叠第二修饰器。
- 延迟色阶≤100ms绿、101–300ms琥珀、>300ms红只影响展示；失败仍是错误色，不改路由或探测阈值。所有编辑弹窗和删除确认弹窗均用默认半透明遮罩与18dp阴影，背景无高斯模糊；预览和输入背景复用相同TextField Colors。

## Alternatives considered

- 保持空列表时开关强制禁用更简单，但用户需要先添加镜像才能启用该设置，且配置开关与资源可用数量被混为一谈；保留独立开关，让空列表时资源层直接回退。
- 为保持原下拉外观继续手绘覆盖菜单，能精准控制单项布局，但重复 Miuix 的选择语义、默认间距与展开／关闭状态；改用受支持的官方下拉组件。
- 将仍在运行的测试也一并遮挡禁用，会阻断用户取消耗时工作；仅停止按钮在活动期间保持可用。
- 不继续维护可选择升降序的`MirrorOrder`／`mirror.order`显示偏好：它已无操作入口，会让旧手动／降序配置继续锁住不符需求的列表；删除该显示模型，在正常写入时清理遗留key。底层镜像源列表顺序另作资源请求失败回退合同，保持不变。
## Consequences

设置停用仍禁用并遮罩其依赖操作，空列表仍可启用。原有储存列表次序仍作为资源失败回退优先级，不被仅用于显示的延迟排名或手动排序覆盖。测速runner由AppContent跨设置路由保存；完整全量测试后一次性选择最快成功项，单项测试和取消不改当前选择。Miuix根主题提供统一回弹；主Pager使用Miuix spring导航，设置栈保留NavDisplay。编辑保存与删除仍严格等待原SettingsSession真实确认，草稿不因外部导航失效而误提交。

Kotlin 回归新增覆盖排序、稳定最快项、全量与单项／失败／停止选择边界、目标变化失效和延迟色阶，CI门槛同步为178项。Python 75项、结构检查与diff检查通过；Kotlin构建未本地运行，双端 Actions 尚未触发。Miuix API核对基于固定0.9.4源码；真机键盘、读屏、色阶可读性及弹窗视觉仍需 Android/iOS 验收。
