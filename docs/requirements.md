# 需求与范围

## 1. 产品目标

创建 Android / iOS 双端订阅管理与代理节点测速工具。产品名已由用户确定为 **ohmydrift**，取漂流、轻盈滑行的意象。appId、bundleId、仓库名及商标/商店重名检查仍待处理。

创建独立的 Android / iOS 共享工程，不混用多套前端框架。

## 2. 平台

- iOS 最低版本：**16.0**，用户已确定。Xcode App target、共享 Kotlin framework、Go 库及其他原生依赖都必须满足；不能只改一个项目设置。
- Android 最低版本：**Android 13 / API 33**，用户已确定；接入同版 `miuix-blur`。
- `minSdk` 与 `compileSdk` / `targetSdk` 是不同概念；最低系统版本不决定使用旧编译 SDK。
- 第一版以 Android arm64、iOS 真机 arm64、iOS Simulator arm64 为验证重点；其他 ABI 按需要增加。
- 共享 UI 的五个一级入口已确定为 **概览、订阅、测速、节点库、设置**；入口形态不代表业务已经接通，功能规划与当前实现见[五页分工](page-functions.md)。
- 不把 Desktop、Web、Server 作为第一版交付目标。
- 不假设 Miuix 示例项目的最低系统等于库最低系统。其 iOS 示例含 17.6 / 26.0 设置，不能直接照抄到本项目。

## 3. 第一版建议功能（待产品确认）

1. 订阅：添加 URL、导入文件/文本、刷新、删除、查看导入数量及错误。
2. 节点：列表、名称/协议/来源展示、搜索、选择、筛选、排序。
3. 测速：延迟预检、下载速度；上传作为可选功能，取决于测速端点能力。
4. 控制：启动、停止、逐节点进度、完成/失败、已耗流量提示。
5. 结果：延迟、抖动、请求失败率、吞吐、错误原因；必要的导出与分享。
6. 设置：明暗模式、测速目标、超时、测试体积、并发策略、蜂窝流量提醒。

已确认设置扩展：非敏感配置使用本地 DataStore，增加延迟节点并发、流媒体与 AI 偏好、GitHub 镜像管理与真实 HTTP 探测／实时排序；镜像手动选择优先，实际请求失败后按持久化顺序降级。流媒体／AI 当前只做配置层，检测核心仍是后续接入范围，不能以设置存在冒充支持。具体存储与安全边界见[设置与镜像](settings.md)。

不在第一版默认包含：全局 VPN、系统流量接管、流媒体解锁检测、Sub-Store 服务、定时爬取、云端账号、自动向 Gist/仓库上传节点、动态下载执行插件。

## 4. Go 核心与协议

- 测速在用户手机执行，而不是在 Actions 或远程服务器代测。
- 不启动独立 mihomo 可执行程序。需要的协议代码作为 Go 依赖编译进原生库，随 App 分发。
- 协议最终能力来自固定版本的 Mihomo；订阅解析器本身不等于协议实现。
- 建立兼容矩阵：输入格式 × 协议 × 传输/TLS 配置 × Android/iOS。只有真实通过创建与连接测试的条目才能标记为已支持。
- 仅 App 自身通过代理访问测速目标，一般不需要 Android VpnService / iOS Packet Tunnel。若增加系统代理能力，作为独立范围评估。
- 现有 VPN 可能改变连接路径，结果应提示当前网络条件，不能保证自动绕过第三方 VPN。

## 5. 订阅解析

参考 subs-check-pro 的本地解析，覆盖 Clash/Mihomo 配置、常见分享链接及 Base64、Sing-box 转换、SSR/WireGuard URI 和必要容错。实际导入支持逐步验收，不承诺完整兼容所有非标准格式。

- 规范配置优先，猜测解析为可选容错；裸 IP:端口推断必须标注为候选协议。
- Sing-box 转换需要检查字段损失，特别是 TLS enabled、Reality、传输参数。
- provider URL 解析需明确入口、递归上限、循环检测、超时与大小限制。
- 不自动上传订阅到第三方转换服务。
- 逐节点错误隔离：单个无效节点尽量不使整份订阅失败。
- 返回失败原因、解析格式、原始/有效/重复/不支持数量。

## 6. 去重要求

默认采用保守的配置等价去重，而非只按 server:port。

- 忽略名称、显示标签等非连接字段；合并节点时保留所有来源关联。
- 协议、服务器、端口及影响连接的凭证、传输、TLS 等参数必须参与识别。
- 密码、私钥、token、路径大小写不能统一转小写；WS 查询参数不能擅自删除。
- 组合凭证完整参与：SOCKS/HTTP 用户名和密码、TUIC UUID 和密码。
- SS cipher、Reality short-id / 公钥等不能遗漏。
- 只有明确可等价的域名、IP 表示、端口类型等才规范化；未知字段保守保留。
- 同名不等于同节点；冲突只做显示重命名，不按名字删除。
- 同端点分组、同出口 IP 合并可作为额外模式，不替代配置去重。
- 指纹含凭证时仅供内部使用，不写入日志、报告或公开稳定标识。

## 7. 性能、测量与生命周期

- 延迟预筛可有限并发；吞吐测速默认单节点或很低节点并发，避免共享出口竞争污染结果。
- 单节点下载连接数独立控制，不能与同时测速节点数混为一个参数。
- Go 执行连接、计时、传输与统计；Kotlin 只接收采样/结果，不跨边界搬运测速流量。
- UI 事件节流，完整结果不丢失。取消要传递到网络请求、在途连接和资源释放。
- 区分 HTTP 测量延迟与 ICMP Ping；请求失败率不命名为精确底层链路丢包率。
- 吞吐明确 B/s、MB/s、Mbps 与换算关系；历史数据记录测试目标与测量条件。
- iOS 第一版按前台测速设计，不承诺任意后台常驻；原生开发也不能绕过系统限制。

## 8. 安全、许可与验收

订阅 token、节点凭证、GitHub 密钥不得写入公开日志、仓库或 CI。支持删除订阅及相应本地凭证；敏感配置存储与系统备份行为在实现前明确。

clash-speedtest、subs-check-pro、Mihomo 的 GPL 义务不能靠封装为库规避。商业使用/收费本身并非 GPL 禁止事项；闭源分发与组合程序义务、App Store 条款兼容性需单独评估。保留版权、许可证、修改记录及对应源码提供方案。

验收按阶段：结构审查 → Actions 编译/测试 → 双端签名或模拟器产物 → 最低系统真机验证。未运行的不写为通过；本轮不代表双端工程、解析器或桥接已经完成。
