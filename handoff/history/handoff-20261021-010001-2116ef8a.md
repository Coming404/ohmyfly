## 3. 关键决策 (Decisions)

- **存储选型：DataStore Preferences，不是数据库。** 设置与少量镜像用键值/索引字段即可；SQLite/Room 留给未来节点、订阅关联和历史查询。DataStore 不加密，订阅 Token、代理密码、私钥不在其范围，未来须用 Keychain/Android 密钥库。
- **Ktor 3.6.0 + 平台原生引擎**：core 共用，OkHttp 保 Android 证书与连接控制，Darwin 用 NSURLSession。只加 core + 两个 engine + mock(test)，不引入完整网络框架、序列化或 DI。版本经 klibs/Maven/固定源码核对；官方未给 iOS 精确下限，不能声称已证明 iOS16 兼容。
- **镜像探测是独立控制面**：不绑定节点 Go 核心，不借用节点并发/超时参数。固定小样本 + SHA-256 只证明“该 raw 资源在该镜像可用”，release/archive 仍需各自验证。
- **手动优先、失败降级**：用户明确选择“手动选择 + 失败后依次降级”。排序不自动改选；选直连就真的先直连；取消不降级；删除当前项必须显式确认改用直连。
- **延迟与流媒体并发不是 clash-Speedtest 的 `concurrent`**：上游 `concurrent=4` 是**单节点传输连接数**。本 App 拆为：延迟节点并发（8）、单节点连接数（4）、吞吐节点并发固定 1、流媒体节点并发（2）。不要把三个概念合并成一个滑杆。
- **流媒体/AI 只做配置层**：旧需求第一版不含流媒体检测；用户现已要求并发参数并选择“流媒体＋AI”，但探针核心未实现。设置存在不代表检测能力已接通，UI/文档不得暗示已能出解锁结果。
- **UI 结构由子代理提出、主会话落地**：七入口与镜像交互是子代理初稿；具体设置控件、导航与持久化连接由主会话实现，镜像列表/编辑/探测状态由子代理实现并主会话修正。最终排版与文案由主会话负责，不能把设计问题归给子代理。
- **不伪造真实性**：未测显示“未测试”，超时不显示 0 ms，不改写失败为成功，不填充假镜像延迟或假节点。镜像候选全部标注未测试/不背书。
- **平台文件命名与依赖**：平台顶层文件必须用 `.android.kt` / `.ios.kt`，否则 JVM facade 重名（真实构建已失败过）。macOS 分支用 `iosMain.dependencies` 惰性访问器；`findByName("iosMain")?.dependencies` 会在源集尚未创建时静默漏依赖（真实构建已失败过）。
- **不扩大范围**：每轮构建前删旧记录，但不自动续用历史授权。安装包只留 GitHub，不下载、不套外层 ZIP、不开公开 Release/商店；IPA 用户自行重签。
